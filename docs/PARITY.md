# Scientific parity and reproducibility

`hina-js` uses the Python HINA implementation at commit
[`f7bb3df3609aa6b0b6d5c98108e940f662053bb5`](https://github.com/SHF-NAILResearchGroup/HINA/tree/f7bb3df3609aa6b0b6d5c98108e940f662053bb5)
as its fixed scientific baseline. Live upstream branches and unpinned PyPI
releases are not test or fixture inputs.

## What is checked

The checked-in fixture
`tests/fixtures/upstream-f7bb3df/yu-hina-long.golden.json` was generated by the
pinned Python source through `scripts/python-oracle.py`. Its input is the
publishable practice dataset `examples/data/yu-hina-long.csv`:

- 391 interaction records (392 physical lines including the header);
- SHA-256 `c92ca7fd40b3241bdb52186b6a498fa36a68a3cf5775627876df8cca28ad9263`;
- 86 distinct `StudentId` values, seven `Code` values and two `Lesson`
  values;
- a 93-node, 317-edge weighted bipartite graph; and
- a 100-node, 391-edge weighted tripartite representation with 14 joint
  `Code`/`Lesson` objects.

The fixture records the complete canonical weighted edge lists, individual
quantity and diversity, global and fixed-actor pruning, fixed-`B=2` community
partitions and MDL values, all cosine projection similarities, and the
community-specific object projections produced from the tripartite graph.
`tests/sample-data.test.ts` compares the TypeScript implementation with those
values end to end. `tests/property.test.ts` supplements the golden example with
deterministic fast-check properties for row ordering, duplicate aggregation,
normalization domains, pruning partitions, edge orientation, non-mutation and
fixed-community co-membership.

## Comparison rules

| Result | Acceptance rule |
| --- | --- |
| Source hash, columns, nodes, edges, weights and counts | Exact |
| Binomial trials, thresholds and significant edge sets | Exact |
| Quantity, normalized quantity, diversity and cosine similarity | `abs(actual - reference) <= 1e-12 + 1e-10 * abs(reference)` |
| MDL description length and compression ratio | `abs(actual - reference) <= 1e-10 + 1e-9 * abs(reference)` |
| Communities | Exact partition/co-membership; numeric labels are ignored |
| Tripartite object projection | Exact canonical endpoint labels and integer weights |

Community numbers are presentation labels, not scientific output. Python builds
its merge heap from sets, so those labels—and, on tied inputs, potentially the
merge path—can depend on `PYTHONHASHSEED`. The fixture therefore stores each
community as a sorted member set, and the TypeScript test compares all unordered
co-membership pairs. The TypeScript implementation uses deterministic tie
breaking and canonical labels.

The fixture pins `PYTHONHASHSEED=0`. An additional audit of seeds `1` and `42`
must compare partitions/co-membership rather than raw JSON: dependency metadata
and last-bit floating accumulation can legitimately differ. For the 391-row Yu
fixture, the three seeds produce the same bipartite and tripartite partitions
and object-projection edge sets; observed MDL variation stays below
`4e-13` in description length.

## Reproduce the Python oracle

The runner imports only the five scientific Python modules from a local
checkout. It intentionally avoids `hina.__init__`, which also imports the web
dashboard stack. The environment used for the checked fixture was:

```text
Python 3.11.16
networkx 3.5
numpy 2.3.3
pandas 2.3.2
scipy 1.16.1
PYTHONHASHSEED 0
```

From the repository root, prepare a sparse checkout of exactly the files used
by the oracle:

```bash
git clone --filter=blob:none --no-checkout \
  https://github.com/SHF-NAILResearchGroup/HINA.git \
  output/upstream-hina-f7
git -C output/upstream-hina-f7 sparse-checkout init --no-cone
git -C output/upstream-hina-f7 sparse-checkout set \
  /hina/construction/network_construct.py \
  /hina/individual/quantity.py \
  /hina/individual/diversity.py \
  /hina/dyad/significant_edges.py \
  /hina/mesoscale/clustering.py \
  /setup.py \
  /requirements.txt
git -C output/upstream-hina-f7 checkout --detach \
  f7bb3df3609aa6b0b6d5c98108e940f662053bb5
```

Create the isolated scientific environment and verify the committed fixture:

```bash
python3.11 -m venv output/python-oracle-venv
output/python-oracle-venv/bin/pip install \
  networkx==3.5 numpy==2.3.3 pandas==2.3.2 scipy==1.16.1
PYTHONHASHSEED=0 output/python-oracle-venv/bin/python \
  scripts/python-oracle.py \
  --input examples/data/yu-hina-long.csv \
  --upstream-root output/upstream-hina-f7 \
  --check tests/fixtures/upstream-f7bb3df/yu-hina-long.golden.json
```

The runner refuses a checkout whose `HEAD` is not the pinned commit, records a
SHA-256 digest for every imported upstream source file, rejects non-finite JSON
numbers, and compares canonical JSON byte for byte in `--check` mode. To inspect
another hash seed without touching the checked fixture, write to `output/`:

```bash
PYTHONHASHSEED=42 output/python-oracle-venv/bin/python \
  scripts/python-oracle.py \
  --input examples/data/yu-hina-long.csv \
  --upstream-root output/upstream-hina-f7 \
  --output output/yu-hina-seed-42.json
```

Regenerate the committed file only as an intentional parity-baseline change:

```bash
PYTHONHASHSEED=0 output/python-oracle-venv/bin/python \
  scripts/python-oracle.py \
  --input examples/data/yu-hina-long.csv \
  --upstream-root output/upstream-hina-f7 \
  --output tests/fixtures/upstream-f7bb3df/yu-hina-long.golden.json
```

After regeneration, review the semantic JSON diff, confirm the input and
upstream source hashes, run the multi-seed partition audit, and then run:

```bash
npm test -- --run tests/property.test.ts tests/sample-data.test.ts
```

The fast-check suites use the fixed seed `20260824`, so a failure is directly
repeatable in addition to fast-check's normal shrink/replay output.

## Intentional cross-language differences

Parity applies to valid, unambiguous scientific inputs. The TypeScript API
intentionally replaces several Python-specific behaviors:

- graph and result values are acyclic, JSON-safe objects rather than NetworkX,
  pandas, tuple-key dictionaries or sets;
- stable node IDs include partition and scalar type, avoiding collisions that
  NetworkX would merge;
- tripartite joint objects retain structured component values and use the
  upstream `Code**Lesson` representation only as a display label;
- construction rejects conflicting attributes by default, with explicit
  `first` or `last` compatibility modes;
- diversity returns finite zero for a zero/one-category limit instead of NaN;
- empty and singleton pruning have the same result shape as general pruning;
- invalid ranges and partitions raise structured validation errors; and
- analyses clone their outputs and do not mutate the input graph.

These differences are validated as API safety properties and are not treated
as numerical parity failures.
